Ubuntu 下 Google Chrome 的安装、卸载与验证

在 Ubuntu 上安装 Google Chrome 的两种可靠方式（官方仓库 / 直接装 deb），以及安装后如何验证、如何彻底卸载清理，附无图形界面的服务器验证方法

2026-10-25
阅读时长: 2 分钟
loading... 次

Chrome 在 Ubuntu 上的官方包名叫 google-chrome-stable。它不在 Ubuntu 默认软件源里，所以得从 Google 自己的源或 deb 包安装。下面按「先装对 → 再验证 → 最后能干净卸载」的顺序写，照着做即可。

文中命令以 Ubuntu 20.04 / 22.04 / 24.04（amd64） 为准，需要 sudo 权限。其他 Debian 系发行版（如 Linux Mint、Pop!_OS）步骤基本一致。

一、安装前准备

  1. 确认系统是 64 位： 
    1
2

    uname -m
# 输出 x86_64 即可，Chrome 仅提供 64 位 Linux 版
  2. 能访问外网（deb 与密钥都从 dl.google.com 下载）。国内网络若慢，可换镜像或挂代理，但不要从第三方站下载 deb，避免被植入篡改包。
  3. 更新一下本地包索引（可选，但能减少依赖冲突）： 
    1

    sudo apt update

二、方法一：通过官方仓库安装（推荐）

仓库方式会把 Google 的签名密钥和源加入系统，之后 sudo apt upgrade 就能跟着一起升级 Chrome，省去手动重装。

# 1. 创建存放密钥的目录（/etc/apt/keyrings 是推荐位置）
sudo install -m 0755 -d /etc/apt/keyrings

# 2. 下载 Google 签名公钥并转成 gpg 二进制格式
sudo wget -q -O - https://dl.google.com/linux/linux_signing_key.pub \
  | sudo gpg --dearmor -o /etc/apt/keyrings/google-chrome.gpg
sudo chmod a+r /etc/apt/keyrings/google-chrome.gpg

# 3. 写入软件源（stable 通道）
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/google-chrome.gpg] \
  http://dl.google.com/linux/chrome/deb/ stable main" \
  | sudo tee /etc/apt/sources.list.d/google-chrome.list > /dev/null

# 4. 更新索引并安装
sudo apt update
sudo apt install -y google-chrome-stable

如果第 2 步 gpg --dearmor 提示找不到 gpg，先装一下：sudo apt install -y gnupg。

三、方法二：直接下载 deb 包安装

不想加源、只想一次性装好，用这个方法最快。缺点是不能随系统自动更新，升级得重新下载。

1
2
3
4
5
6
7
8

# 1. 下载最新稳定版 deb
wget https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb

# 2. 安装（apt 会自动处理依赖，包括拉取 libnss3 等）
sudo apt install -y ./google-chrome-stable_current_amd64.deb

# 3. 装完可删除下载的 deb
rm -f google-chrome-stable_current_amd64.deb

注意 ./ 不能省：直接 apt install 文件名.deb 会被当成「从源里找叫这个名字的包」而报错，加上 ./ 才表示「本地文件路径」。

四、验证安装是否正确

装完后别急着用，先确认装的是 Google 官方版本、路径也在预期位置。

 1
 2

# 1. 看版本号（能正常输出版本即安装成功）
google-chrome-stable --version
# 例：Google Chrome 130.0.6723.58

# 2. 看可执行文件装到哪了
which google-chrome-stable
# 正常返回：/usr/bin/google-chrome-stable

# 3. 校验签名来源（确认是 Google 的包，而非第三方）
apt-cache policy google-chrome-stable
# 输出里应有 *** 标记来自 dl.google.com/linux/chrome/deb 的行

有图形界面时，直接按 Super 键搜 “Chrome” 或在终端运行 google-chrome-stable & 即可启动。

无图形界面的服务器验证（headless）

服务器通常没桌面，无法开窗口，用无头模式跑一个最小验证：

1
2
3

# 连 GPU / 沙箱都不需要，能正常拉回页面 DOM 即代表可用
google-chrome-stable --headless --no-sandbox --disable-gpu \
  --dump-dom https://www.google.com | head -n 5

--no-sandbox 在 root 用户或受限容器里常是必需的；正常桌面用户不必加。如果报错 error while loading shared libraries，多半缺依赖，执行 sudo apt install -y libnss3 libatk-bridge2.0-0 libgtk-3-0 补齐即可。

五、卸载与彻底清理

1. 卸载主程序 

1
2
3
4
5
6
7
8

# 仅移除程序，保留个人配置
sudo apt remove google-chrome-stable

# 连配置文件一起删（purge）
sudo apt purge google-chrome-stable

# 清理因依赖它而装、现已无用的包
sudo apt autoremove

2. 清理仓库方式留下的源与密钥

如果你用的是「方法一」，卸载后最好把源和密钥一并删掉，否则 apt update 仍会去连 Google 的源：

1
2
3

sudo rm -f /etc/apt/sources.list.d/google-chrome.list
sudo rm -f /etc/apt/keyrings/google-chrome.gpg
sudo apt update   # 确认不再报 Google 源相关错误

3. 删除用户个人数据（可选）

浏览器缓存、登录态等存在用户目录，上面步骤不会动它。需要彻底清空：

1

rm -rf ~/.config/google-chrome

六、常见问题

Q：安装时提示 N: Download is performed unsandboxed as root？ 只是 apt 的提示信息，不是错误，deb 已正常装好，可忽略。

Q：启动时报 Failed to move to new namespace？ 沙箱在容器 / 某些内核配置下会失败，加 --no-sandbox 启动，或在服务器场景直接用上面的 headless 命令。

Q：想装测试版 / 开发版？ 包名分别是 google-chrome-beta 和 google-chrome-unstable，用同样的方式把 google-chrome-stable 换成对应名字即可。

Q：怎么确认没装成第三方改包？ 用 apt-cache policy google-chrome-stable 看版本来源是否来自 dl.google.com/linux/chrome/deb，再核对 apt-key list 或 /etc/apt/keyrings/google-chrome.gpg 的指纹是否与 Google 官方公布一致。

按上面的顺序，安装、验证、卸载都能干净走通。日常使用推荐「方法一」的仓库方式，升级省心；一次性临时用选「方法二」更快。
